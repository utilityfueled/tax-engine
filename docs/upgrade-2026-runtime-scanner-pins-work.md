- Pin Syft 1.57.1 for both software inventory formats and Grype 0.121.3 for vulnerability reporting. The release notes document fixes in their embedded dependencies, including Brotli and Go `x/net`. Grype also updates its Docker SDK dependencies. The workflow checks the versions reported by the tools and continues to verify the immutable image identity, report all findings, and fail on critical findings. [Syft 1.57.1 release](https://github.com/anchore/syft/releases/tag/v1.57.1), [Grype 0.121.3 release](https://github.com/anchore/grype/releases/tag/v0.121.3)
- Verified the local Darwin arm64 scanner release archives against the publishers’ SHA-256 files. Downloaded Grype schema v6.1.10 from Anchore’s public listing and verified its published archive checksum. Grype imported and validated the database built at 06:20:58 UTC on November 12, with automatic updates disabled and the existing 120-hour age limit. [Anchore database documentation](https://oss.anchore.com/docs/guides/vulnerability/database/), [Anchore database listing](https://grype.anchore.io/databases/v6/latest.json)
- Scanned the exact upstream Linux amd64 and arm64 Node 26.13.1 OCI archives. Each produced 225 software components and 221 vulnerability matches across 109 unique identifiers. Each reported 68 High matches and zero Critical matches. Three Debian matches showed a fixed version, all for `zlib1g`; the separate zlib package installs that version. Six High npm matches were located under the upstream npm installation removed by the application image build. This evidence covers the upstream base images before the zlib installation and application layers. [Debian zlib security advisory](https://security-tracker.debian.org/tracker/DSA-6613-1)
- The new workflow pin test failed before the workflow change. Both scanner contract tests and eight runtime contract tests passed afterward. Scoped ESLint and Git whitespace checks passed. `actionlint` passed its workflow validation with its optional shellcheck adapter disabled. With the adapter enabled it reported the same three shellcheck diagnostics as the unchanged workflow.
- CI and the native rehearsal still need to build the composed application image, verify its runtime behavior, scan its actual contents, and review the remaining findings against release policy. The upstream scans qualify only the scanner and base-image inputs.
